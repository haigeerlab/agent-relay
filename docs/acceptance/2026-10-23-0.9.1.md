## 发现

1. **`runtime` 的 `next` 与 CHANGELOG 不一致（文案，小）。** CHANGELOG `[0.9.1]` 说这个 warn “可以不理、不用跑
   `upgrade --confirm`”，doctor 的 `next` 却仍然写着 `close the sessions using the mailbox, then run upgrade --confirm
   after the user agrees`。只照 doctor 操作的用户可能会去停 bridge、升级运行时。CHANGELOG 已说明根因会在后续小版本里修
   （`bridge/UPSTREAM.sha256` 哈希变化），修的时候一并改掉这条建议即可。属于产品文案，归 `runtime` 检查所在的模块。
2. **`next` 里各步骤的顺序没有按标签分组（观感，很小）。** 用户级的 marketplace update 和 `update --scope user`
   夹在 local 卸载命令中间，第 2 条 local 命令之后、第 3 条之前。逐条执行的结果没有问题，只是读起来不如“先 local、后
   user”或“按标签分组”清楚。不影响验收结论。

结论：Acceptance 一节的两半都通过。清理前，有旧标签时 `claude-plugin` 报 warn，并写明标签和实际加载的版本；照建议
清理后报 ok，`claude plugin list` 不再有不一致的标签。Codex 侧也通过。
