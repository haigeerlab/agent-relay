# 决策：XATS 协作传输的日落条件

状态：已批准（2026-09-28，用户决定）。尚未触发，XATS 仍是默认传输。

## 背景

协作邮箱有两套传输：

- **XATS**：默认传输，在已接受的 `collaboration-messaging` Proposal 范围内。无选择标记时使用它。
- **native**：实验性传输，只能经单独审批的切换启用。它的唤醒依赖宿主的私有应用 IPC，不是公开接口；目前在一台
  主机上通过受控唤醒试验，并通过两主机与双 Chrome 的普通验收。

两套并存的成本：约 1,990 行实现与相当规模的测试、三个第三方运行时、最多四个宿主 MCP 条目、`collab` skill 里的
两套协议。2026-09-27 的审计把它列为“疑似过度设计”，建议给 XATS 定日落条件。

协作 Spec 已规定：把 native 提升为默认是新需求，必须走 Proposal 流程。因此 XATS 的退出以 native 转正为前提。

## 决策

### 1. native 转正的证据门槛

只有同时满足以下条件，才可以提出“native 成为默认传输”的 Proposal：

1. **多主机、多版本验收。** 连续两个发布版本，各在至少两台主机上完成实机验收：收发、空闲会话唤醒、回退演练。
   验收记录写入该版本的 `docs/releases/v<version>-*.json`。
2. **升级后唤醒仍然有效。** 至少升级过一次固定的上游 revision（`native_collaboration_runtime.py` 的
   `BRIDGE_COMMIT`），升级后唤醒验收仍然通过。这用来证明对私有 IPC 的依赖不是一次性的巧合。
3. **没有未关闭的 native 缺陷。** 不存在 P1 或 P2 级别的 native 问题。

门槛只决定能不能提出 Proposal，是否转正仍由 Proposal 评审与人工接受决定。

### 2. XATS 的退出节奏：一个 minor 过渡

- **转正版本（N）**：native 成为默认；XATS 的 `status` 与安装命令输出废弃提示，并链接迁移指南；新增迁移指南，
  说明归档、切换与回退。
- **下一个 minor（N+1）**：删除 XATS 的运行时启动、宿主适配器、Claude launcher 与 tmux 提醒。保留 XATS 邮箱归档
  的只读读取，以及 `uninstall-claude` / `uninstall-codex`，让尚未清理的用户能移除旧条目。
- 已有 XATS 邮箱的内容不删除；是否清理由用户自己决定。

### 3. 反向出口

如果门槛长期无法满足，特别是私有 IPC 在宿主升级后失效且无法修复，应改为评估淘汰 native，而不是让两套传输无限期
并存。这需要单独的决定。

## 影响

- 本决策不改变任何代码或默认行为；XATS 仍是默认，native 仍是实验性选项。
- 审计的“XATS 与 native 双传输”一项由此从“未裁剪”变为“已定日落条件，待触发”。
- 本机（审计所在的 Mac）已经切换到 native，XATS 的服务与宿主条目已移除；这台机器可以作为门槛第 1 条的两台主机
  之一，但还需要另一台主机。
