# 兼容协作传输退役说明

从 v0.40.0 起，Spec Guard 的同机 Claude Code／Codex 协作只使用 native bridge。旧守护进程、HTTP／token
适配器、backend selector、切换与回退命令不再随插件提供；native 不可用时会明确停止，不会恢复旧传输。

## 升级影响

- v0.39.0 及更早版本的已加载会话不会被源码仓库自动替换。安装 v0.40.0 后，应在新会话中确认插件版本与
  native MCP 工具面，再进行一次双向收发和空闲唤醒验收。
- 用户目录中既有的旧邮箱数据库不会被读取、迁移或删除。它只留作用户私有历史数据，不影响 native 邮箱。
- 新安装不会创建或继承旧邮箱数据；native 的用户级邮箱状态由本机运行时按需创建，不存放在消费者项目目录。
- 插件升级不会自动修改 Claude Code 或 Codex 的全局配置，也不会自动清理旧 LaunchAgent 或 MCP 条目。
  如本机仍有残留，应先只读核对精确条目，再经用户明确授权清理。
- 项目内预配的 Claude 权限仍只属于该项目；它可以减少已授权会话的重复确认，但不会让其他项目或新安装者继承。

## 验收与故障处理

发布后验收必须区分源码测试与真实宿主证据。至少确认 Claude Code ↔ Codex 双向消息、确认回执、同一空闲会话
重复唤醒，以及宿主只暴露审核过的 mailbox 工具集合。若其中任一项失败，先修复 native 或宿主配置；不要启动、
恢复或重新实现已退役传输来掩盖问题。

架构决定、接受的风险和被取代的旧门槛见
